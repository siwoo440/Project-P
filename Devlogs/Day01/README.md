## 1. 목표

기획서의 핵심 시스템, 프로토타입 범위, Scene 구성과 데이터 흐름을 앞으로 35일 동안 흔들리지 않을 기준선으로 확정한다.

코드를 작성하는 날이 아니라, **구현 도중 되돌아올 일이 없도록 구조를 먼저 못 박는 날**이다.

---

## 2. 확정 사항

### 2.1 Scene 구조

게임 "단계"가 바뀔 때만 Scene을 분리한다. 같은 단계 내부의 화면 변화는 Panel 또는 State 전환으로 처리한다.

| Scene | 책임 |
|---|---|
| `00_Boot` | 전역 시스템·공통 데이터 초기화 |
| `01_Title` | 새 게임 / 이어하기 / 설정 / 종료 |
| `02_MainHub` | 스테이지 밖의 전부 (캐릭터·성장·편성·스테이지 선택) |
| `03_Gameplay` | 스테이지 안의 전부 (이동·전투·상점·이벤트·보상) |
| `90_Ending` | 엔딩·크레딧 (프로토타입 제외) |
| `Dev_PuzzleTest` | 퍼즐 단독 검증 (빌드 제외) |
| `Dev_BattleTest` | 전투 단독 검증 (빌드 제외) |

화면마다 Scene을 만들지 않는다. Room 종류를 Scene 이름으로 분기하지 않고 `RoomData`를 읽은 `RoomManager`가 State와 Panel을 활성화한다.

### 2.2 데이터 3계층

모든 데이터는 아래 셋 중 하나에만 속한다.

| 계층 | 소유자 | 수명 |
|---|---|---|
| `StaticData` | `DataManager` | 영구 불변 (읽기 전용) |
| `SaveData` | `SaveManager` | 영구 (디스크) |
| `SessionData` | `03_Gameplay` | 스테이지 1회 |

절대 규칙 네 가지를 확정했다.

1. UI는 원본 데이터를 직접 수정하지 않고 전용 서비스에 요청한다.
2. MainHub에서 Gameplay로의 전달은 참조가 아니라 값 복사(스냅샷)다.
3. 스테이지 진행 상태는 전부 `SessionData` 안에만 존재한다. `MonoBehaviour`는 상태를 소유하지 않는다.
4. 상점 구매 결과는 `SessionData`에만 반영하고 `SaveData`에 직접 쓰지 않는다.

### 2.3 매니저 수명

- **전역 (앱 종료까지)**: `GameManager`, `SaveManager`, `AudioManager`, `DataManager`, `SceneFlow` — `00_Boot`에서 생성
- **스테이지 한정**: `StageManager`, `RoomManager`, `TurnManager`, `BattleManager`, `PuzzleManager`, `GameplayUIController` — `03_Gameplay`에서 생성·파괴

`DontDestroyOnLoad`는 `00_Boot`에서만 호출한다.

### 2.4 저장 규칙

저장 시점은 스테이지 시작 / 방 이동 완료 / 스테이지 클리어 / 캐릭터 성장 변경 네 개뿐이다. 전투 중간 상태는 저장하지 않는다.

**이어하기와 패배 재도전을 같은 메커니즘으로 통일했다.** 둘 다 "방 진입 직전 `SessionData` 스냅샷"을 되감는 방식이다. 이 결정 덕분에 16일차 재도전 구현이 별도 작업 없이 해결된다.

### 2.5 프로토타입 범위

캐릭터 4명, 스킬 4개, 적 2~3종, 보석 5종, 4×12 보드, 행동력 6, Exploration·Battle State만 구현한다.

보스·성장·상점·이벤트·스토리·게임패드·엔딩은 범위에서 제외한다.
