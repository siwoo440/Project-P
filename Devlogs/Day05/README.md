## 2. 구현 내용

### 2.1 규칙과 화면 분리

| 역할 | 구성 | 설명 |
|---|---|---|
| 규칙 | `Board`, `BoardPosition`, `BoardGenerator` | Unity에 의존하지 않는 순수 C#. Play 없이 자동 테스트할 수 있다 |
| 화면 | `BoardView` | Board를 읽기만 하고 수정하지 않는다 |
| 연결 | `PuzzleManager` | 규칙과 화면을 묶는다. Dev_PuzzleTest와 03_Gameplay가 같은 컴포넌트를 쓴다(기획서 12.15) |

5~10일차 퍼즐 규칙은 숫자와 조건이 많아 눈으로 확인하기 어렵다. 이 컴퓨터는 Play 모드도 불안정하다. 그래서 규칙을 순수 C#으로 분리해 자동 테스트로 검증하는 구조를 먼저 만들었다.

### 2.2 보드 규칙

- **좌표**: 행 0 = 맨 아래, 열 0 = 맨 왼쪽. 칸 번호 = `행 × 열 수 + 열`. 9일차 낙하(행 감소)·보충(맨 위 행부터) 계산을 단순하게 하기 위해 지금 확정했다.
- **생성**: 보석별 가중치에 비례해 뽑는다. 가중치 0인 보석은 나오지 않으므로 특수 보석은 무작위로 생성되지 않는다.
- **재현성**: `System.Random`에 시드를 넘긴다. 같은 시드는 항상 같은 보드를 만든다.
- **자동 셔플 없음**: 모든 일반 보석이 서로 연결되므로 연결할 곳 없는 보드가 생기지 않는다(기획서 5.1).

### 2.3 보석 데이터

| 보석 | 색 | 모양 | 생성 가중치 |
|---|---|---|---|
| 물리 | 빨강 | ◆ 다이아몬드 | 20 |
| 마법 | 파랑 | ★ 별 | 20 |
| 회복 | 초록 | ✚ 십자 | 20 |
| 혼돈 | 짙은 보라 | ✸ 가시 폭발 | 20 |
| 균형 | 아이보리 | ◎ 고리 | 20 |

- 기획서 10.2("색만으로 구분하지 않는다")에 따라 종류별 고유 모양을 넣었다.
- 레거시 문서의 혼돈 색은 검정이지만, 어두운 배경에서 보이지 않아 짙은 보라로 바꿨다.
- 생성 확률은 기획서가 공란이라 5종 균등으로 시작한다.

`PuzzleConfig`(보드 크기)와 `GemData` 5종을 에셋으로 만들고 `GameDatabase`에 연결했다. Boot 시 퍼즐 데이터가 없으면 초기화 실패로 안내한다.

### 2.4 코드 묶음 분리 (asmdef)

| 묶음 | 내용 |
|---|---|
| `ProjectP.Runtime` | 게임 코드 전부 |
| `ProjectP.Editor` | 조립 메뉴 등 에디터 도구 |
| `ProjectP.Tests.EditMode` | 자동 테스트 |

Unity 자동 테스트는 기본 코드 묶음을 참조할 수 없어서 분리가 필요했다. 부수 효과로 코드를 고친 뒤 컴파일 시간도 줄어든다.

### 2.5 UI 디자인

**디자인 값**
- 색·스프라이트는 `UITheme` 에셋 한 곳에서 관리한다. 색을 바꾸고 Build All을 다시 실행하면 전체 화면에 반영된다.
- 색 구성: 짙은 남색 배경 그라디언트, 금색 강조, 따뜻한 흰색 글자.

**그래픽**
- 코드로 그린 임시 그래픽 12종: 둥근 사각형, 외곽선, 부드러운 그림자, 원, 빛 번짐, 배경 그라디언트, 보석 타일, 보석 아이콘 5종.
- 부호 있는 거리 함수로 계산해 가장자리가 매끄럽다.
- 아트가 확정되면 스프라이트만 교체한다.

**부품**
- 버튼 3종: Primary(금색) / Secondary(어두운 면 + 외곽선) / Danger(빨강). 그림자, 마우스 반응, 비활성 시 글자 흐림을 넣었다.
- 둥근 카드(그림자·외곽선), 슬라이더(금색 채움·원형 손잡이), 입력칸, 태그를 만들었다.

**화면**
| 화면 | 구성 |
|---|---|
| 00_Boot | 보석 장식, 로고, 금색 로딩 막대, 실패 시 빨간 오류 카드 |
| 01_Title | 보석 5개 아치 장식, 로고와 금색 밑줄, 메뉴 버튼, 버전 표시. 확인창의 "예"는 Danger 버튼 |
| Dev_PuzzleTest | 상단 바(DEV 태그·보드 크기), 시드 카드, 보석 분포 카드, 하단 6×12 보드 |

**조립 메뉴**

- `Project P > Rebuild > ...`: 화면 하나만 다시 조립한다.

## 3. 검증

### 3.1 컴파일

Unity 내장 컴파일러로 코드 묶음 4종(게임 빌드용 런타임, 에디터용 런타임, 에디터 도구, 테스트)을 따로 컴파일했다. 오류 0건. 에디터에서도 컴파일 오류가 없었다.

### 3.2 자동 테스트

- **에디터 밖 실행**: Unity 번들 .NET 런타임으로 12개를 직접 실행했다. 12개 통과, Unity 전용 1개는 건너뜀.
- **버그 검출 확인**: 복사본에서 좌표 계산을 일부러 뒤집자 테스트 2개가 실패했다. 테스트가 실제로 버그를 잡는다는 뜻이다.
- **에디터 Test Runner**: **13/13 통과** (`TestResults.xml`).

테스트 항목은 다음과 같다.
- 보드 크기 6×12 기본값
- 요청한 크기로 생성
- 잘못된 크기 거부
- 좌표 시작점(맨 아래 왼쪽)과 순서
- 좌표와 칸 번호의 왕복 변환
- 범위 판정, 범위 밖 접근 시 예외
- 모든 칸이 기본 보석으로 채워지는지
- 같은 시드 → 같은 보드, 다른 시드 → 다른 보드
- 가중치 0인 보석 미생성
- 가중치 비율대로 뽑히는지(10만 회, ±1.5%)
- 잘못된 가중치 거부

### 3.3 조립 결과

- Build All의 6단계가 모두 완료됐다.
- `GameDatabase`에 PuzzleConfig(6×12)와 보석 5종이 연결됐다.
- 00_Boot의 Bootstrapper에 새 Boot 화면이 연결됐다.
- 세 화면의 조립 루트가 생성됐다. 조립 도구는 필드 연결에 실패하면 예외를 던지는데, 완료까지 예외가 없었다.

### 3.4 미확인

실행 기록으로 판단할 수 없는 항목이다.

- Dev_PuzzleTest에서 Play 시 보드 표시, 새 보드, 시드 재현, 분포 표시
- 새 디자인의 Boot·Title 화면 실제 모습
