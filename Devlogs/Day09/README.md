# 9일차 — 동일 종류 연속·연속 강화·특수 보석

**날짜**: 2026-09-23
**단계**: 2단계 · 퍼즐 프로토타입
**상태**: 완료

---

## 1. 목표

- 같은 종류 보석을 끊지 않고 이으면 2번째부터 효과가 **+20%씩 누적**된다(기획서 5.5).
- **4연속**이면 종류에 맞는 연속 강화 효과, **5연속 이상**이면 경로 마지막 칸에 특수 보석을 만든다(기획서 5.6).
- **사용자 요청으로 추가했다**: 잇는 동안 어떤 배율과 효과를 받고 있는지 실시간으로 보여준다.

보석 제거·낙하·보충은 7일차에 앞당겨 끝냈다.

---

## 2. 결정 사항

기획서에 수치가 비어 있어 제안값을 그대로 적용했다. 값은 모두 `PuzzleConfig` 에셋에서 바꿀 수 있다.

| 항목 | 적용값 |
|---|---|
| 연속 보너스 | 2번째부터 +20% 누적, **상한 없음**. 행동력이 경로 길이를 막는다(최대 9 → 260%) |
| 배율이 붙는 효과 | 피해·회복만. 혼돈·균형은 1씩이라 4연속 보너스로 보상한다 |
| 강공격 (물리·마법 4연속) | 그 구간 피해 합 × 50%를 한 번 더 |
| 추가 회복 (회복 4연속) | 그 구간 회복 합 × 50%를 더 |
| 지연 강화 (혼돈 4연속) | 지연 +1. 한 번 연결에 +2인 상한과 별개 |
| 균형 4연속 | 다음 턴 행동력 +1 (기획서 값). 다음 턴 보너스 상한 +3은 지킨다 |
| 특수 보석 효과 | 물리: 한 적에게 물리 × 3 / 마법: **모든 적**에게 마법 × 1.5 / 회복: 회복력 × 3 / 혼돈: **모든 적** 행동 +1 / 균형: 다음 턴 행동력 +2 |
| 특수 보석과 연속 | 특수 보석은 **연속을 끊고** 연속 배율도 받지 않는다. 피버(10일차) 배율은 받는다 |
| 특수 보석 생성 | 한 번 연결에 **1개**. 조건을 넘긴 구간이 여럿이면 마지막 구간 종류 |

- 특수 보석 수치는 처음에 `GemData`에 두려 했다. 기존 보석 에셋 5개를 고치지 않아도 기본값이 들어가도록 `PuzzleConfig`로 옮겼다.
- 회복 특수 보석의 "상태 효과 1개 제거"는 상태 효과가 생기는 전투 단계에서 추가한다.

## 3. 구현 내용

### 3.1 규칙 (순수 C#)

| 구성 | 역할 |
|---|---|
| `PathGem` | 경로 안 보석 하나: 종류 + 특수 보석 여부 |
| `ChainBonus` | 같은 종류가 이어진 구간 찾기, 칸별 연속 배율, 만들 특수 보석 종류 |
| `ChainSettings` | 연속·연속 강화·특수 보석 수치 |
| `GemEffectResolver` | 연속 배율 적용, 4연속 구간이 끝나는 자리에 연속 강화 1건 추가, 특수 보석 효과 |
| `GemEffect` | 효과마다 출처(일반 / 연속 강화 / 특수)와 대상(한 적 / 모든 적). 결과표에 칸별 배율·만들 특수 보석·연속 강화 횟수 |
| `Board` | 칸마다 특수 보석 여부 |
| `BoardGravity` | 특수 표시가 보석과 함께 떨어지고, 새로 채우는 보석은 늘 일반 보석 |

- 연속 강화는 구간 마지막 보석 **바로 뒤**에 처리한다. 연결 순서대로 처리하는 규칙(기획서 5.5)을 그대로 지킨다.
- 8일차에 만든 외부 배율 자리는 그대로 남겼다. 10일차 피버 +50%가 여기에 곱해진다.

### 3.2 연결

| 구성 | 변경 |
|---|---|
| `PuzzleConfig` | 연속 보너스·연속 강화·특수 보석 생성 기준·특수 보석 효과 수치 12개 추가 |
| `PuzzleManager` | 5연속이면 경로 마지막 칸을 없애지 않고 특수 보석으로 바꾼 뒤 낙하시킨다. 지금 경로를 놓았을 때의 효과를 미리 계산하는 `PreviewEffects` 추가 |
| `BoardView` | 특수 보석은 **금색 테두리 + 천천히 밝아졌다 어두워지는 빛**으로 구분한다. 생길 때 번쩍이며 한 번 튀어 오른다 |

### 3.3 실시간 배율 표시 (사용자 요청)

잇는 동안 두 곳에서 보여준다. 계산은 실제로 놓을 때와 같은 계산기(`GemEffectResolver`)를 쓴다.

- **칸 옆 배율표** (`ConnectionView`)
  - 이은 칸 오른쪽 아래에 그 보석이 받는 배율 `×1.2 · ×1.4 …`를 붙인다. 배율 1.0인 칸은 표시하지 않는다.
  - **4연속째 칸은 청록색**으로 바뀌어 연속 강화가 터지는 칸임을 알린다.
  - 특수 보석 칸에는 `특수`를 붙인다.
- **연결 효과 칸** (`ConnectionPreviewView`, 보드 왼쪽 아래)
  - 마지막 보석과 그 배율(`×1.4`), `물리 3연속`
  - 다음 안내: `다음 물리 ×1.6 · 강공격까지 1개` → `강공격 발동! · 특수 보석까지 1개` → `특수 보석 생성!`
  - 합계: 피해 · 회복 · 지연 · 다음 턴 행동력
  - 발동하는 연속 강화와 특수 보석 생성
  - 잇지 않을 때는 안내 문구만 보인다.

### 3.4 Dev_PuzzleTest

```
[현재 시드]     [허수아비 A · B · C]     [연결 기록]
[메인 캐릭터]
                    [보드 6×12]          [보석 분포 + 연속 보너스 안내]
[연결 효과]
```

- 양옆 칸을 상단 카드 아래부터 보드 카드 아랫변까지 늘렸다.
- 메인 캐릭터 패널을 줄이고 `HP -20` 버튼을 제목 줄로 옮겼다.
- 보석 분포 요약에 특수 보석 수를 표시하고, 아래에 연속 보너스 안내를 넣었다. 안내 수치는 `PuzzleConfig`에서 읽는다.
- 허수아비
  - 모든 적 대상 효과(마법·혼돈 특수 보석)는 살아 있는 허수아비 전원에게 준다.
  - 연속 강화·특수 보석은 `강공격 26`, `특수 18`처럼 이름을 붙여 크게 띄운다.
- 연결 기록에 `연속 강화 N`, `특수 생성`을 표시하고 특수 보석은 밑줄로 구분한다.

## 4. 검증

### 4.1 자동 테스트

- Unity 밖(`verify.sh`): 96개 통과, Unity 전용 1개는 건너뜀. 어셈블리 4종 경고 0
- 에디터 Test Runner: **97/97 통과**

**연속 규칙 `ChainBonusTests` (8개, 새로 추가)**
- 종류가 바뀌면 구간이 나뉨
- 2번째부터 +20% 누적 / 끊기면 다시 100%
- 상한 없음(9연속 260%)
- 특수 보석은 연속을 끊고 배율 없음
- 특수 보석은 끊기지 않은 5연속만 만든다
- 한 번에 1개, 마지막 구간 종류
- 잘못된 입력 거부

**효과 계산 `GemEffectResolverTests` (11개 추가, 기존 테스트는 연속 규칙에 맞게 기대값 수정)**
- 3연속 100/120/140%
- 물리 4연속 강공격 / 회복 4연속 추가 회복
- 혼돈 4연속은 상한 +2를 넘는 지연 강화 / 균형 4연속은 상한 안에서 +1
- 5연속이면 특수 보석 생성, 연속 강화는 한 번
- 끊긴 연속은 연속 강화 없음
- 특수 보석 5종 효과와 대상
- 특수 보석은 연속을 끊고 연속 배율 없음 / 외부 배율은 받음
- 혼돈 특수는 혼돈 상한과 별개, 균형 특수는 다음 턴 상한 안에서

**보드 `BoardGravityTests` (2개 추가)**
- 특수 보석은 표시와 함께 떨어지고 새로 채운 보석은 일반
- 보드는 특수 보석 없이 시작하고, 종류를 바꿔도 특수 표시는 유지

### 4.2 조립·실행

- Build All 완료. Dev_PuzzleTest에 메인 캐릭터·연결 효과·허수아비·보석 분포 패널이 조립됐다.
- 조립 도구가 이름으로 연결하는 새 필드 23개(`BoardView` 2, `ConnectionView` 4, `ConnectionPreviewView` 17)가 스크립트와 모두 일치했다.
- Dev_PuzzleTest Play: Boot를 거쳐 퍼즐 화면으로 돌아왔고 실행 중 오류는 없었다.

### 4.3 참고

- Play 전 에디터 화면에서 TextMeshPro 내부 `IndexOutOfRangeException`이 몇 번 기록됐다.
  - 8일차 커밋 때 동적 한글 폰트 에셋을 되돌리면서, Unity가 이미 불러 둔 글자 텍스처 수와 맞지 않아 생긴 일시 오류다.
  - 이후 Build All과 Play에서는 다시 나지 않았다.
- 작업 중 Unity가 새 스크립트의 `.meta`를 다시 만들었다. 커밋에는 Unity가 만든 것을 넣었다.

## 5. 참고 사항

- **Build All 뒤 씬 ID만 바뀐 파일**: `00_Boot`·`01_Title`은 순서·ID 외 내용 차이가 없어 되돌렸다. 동적 폰트 에셋 변경도 제외했다.
- 특수 보석은 기획서상 전투 종료 시 제거한다. 전투(11일차~)에서 연결한다. 지금은 새 보드를 만들면 사라진다.
- `GemType.Special` 열거값은 쓰지 않는다. 특수 보석은 "종류 + 특수 표시"로 나타낸다.
