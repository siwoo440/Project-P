# 6일차 — 보석 연결 입력

**날짜**: 2026-09-23
**단계**: 2단계 · 퍼즐 프로토타입
**상태**: 완료 · 드래그 조작감은 기록으로 확인 불가

---

## 1. 목표

마우스 드래그로 보석을 이어 경로를 만들고, 손을 떼면 확정한다. 기획서 5.3 기준이다.

- 8방향(상하좌우·대각선) 인접한 보석만 연결
- 최소 2개부터 확정
- 한 경로 안에서 이미 고른 보석 재선택 금지
- 서로 다른 종류도 연결 가능
- 우클릭·ESC로 취소

확정해도 보석 효과·제거는 아직 없다. 효과는 8일차, 제거·낙하는 9일차에 다룬다.

---

## 2. 구현 내용

### 2.1 규칙 (순수 C#)

| 구성 | 역할 |
|---|---|
| `ConnectionPath` | 연결 규칙. 인접 판정, 재선택 거부, 되돌리기, 최소 개수 확정, 최대 개수 자리 |
| `ConnectionResult` | 추가 시도 결과. 추가됨 / 되돌림 / 인접 아님 / 이미 선택 / 보드 밖 / 개수 초과 등 |
| `BoardLayout` | 칸 위치와 마우스 판정 계산. 빠른 드래그 시 지나간 칸 추적 |

- `ConnectionPath`의 최대 개수는 지금 제한이 없다. 7일차에 행동력 값을 넣으면 바로 적용된다.
- `BoardLayout`을 `BoardView`와 `BoardInput`이 함께 쓴다. 칸이 그려지는 위치와 마우스로 판정하는 위치가 어긋나지 않게 하기 위함이다.

### 2.2 조작 결정

기획서에 없던 조작 세부를 다음과 같이 정했다.

| 항목 | 결정 | 이유 |
|---|---|---|
| 직전 보석으로 되돌아가기 | 마지막 선택 취소 | 연결 퍼즐의 일반적인 조작. "다시 고르기"가 아니라 "하나 물리기"라서 기획서 규칙과 충돌하지 않는다 |
| 선택 판정 | 칸 중심 80% 원 안 | 대각선으로 그을 때 모서리를 스치며 옆 칸이 잡히는 문제 방지 |
| 보드 밖에서 놓기 | 확정 | 기획서 "놓는 순간 확정". 1개만 골랐으면 조용히 취소한다 |
| 연결선 색 | 금색 한 가지 | 혼합 연결이 기본이라 보석 색을 따르면 선 색이 계속 바뀌어 산만하다 |

### 2.3 입력과 화면

| 구성 | 역할 |
|---|---|
| `BoardInput` | 보드 영역 하나에서 누름·드래그·놓기를 받아 칸 좌표로 바꾼다. 우클릭은 마우스 입력으로, ESC는 새 Input System의 키보드 입력으로 받는다 |
| `ConnectionView` | 금색 연결선, 이음점, 경로 끝 "N개" 표시. 선과 점을 다른 층에 그려 선이 점을 덮지 않게 했다 |
| `BoardView` | 선택한 보석을 1.08배 확대하고 흰 외곽선을 표시한다. 확정하면 한 번 반짝인다 |
| `PuzzleManager` | 경로를 관리하고 시작·변경·확정·취소를 이벤트로 알린다. 화면은 이 이벤트를 받아 그리기만 한다 |

### 2.4 디자인 조정

- 연결 중 모습을 미리 렌더링해 보니 굵은 금색 점이 보석 아이콘 가운데를 가렸다.
- 선택 표시는 외곽선과 확대가 이미 맡고 있으므로, 선은 14→9, 점은 26→15로 줄였다.
- 보석 타일과 같은 모양의 선택 외곽선 그래픽(`gem_tile_outline`)을 추가하고 `UITheme`에 연결했다.

### 2.5 Dev_PuzzleTest

- 상단 카드를 3개로 늘렸다: 시드 / 보석 분포 / **연결 기록**.
- 연결 기록은 최근 5건을 보석 이름 첫 글자와 보석 색으로 보여준다. 예: `물물마회 4개`
- 기록 카드 오른쪽 위에 "연결 중 · N개"를 실시간으로 표시한다(기획서 12.15의 연결 로그).
- 상단 바에 조작 안내를 넣었다.

### 2.6 검증 도구 저장소 편입

`Tools/Verify/verify.sh`를 추가했다. Unity를 열지 않고 다음 두 가지를 한 번에 한다.

- 어셈블리 4종을 Unity 내장 컴파일러로 컴파일
- 순수 C# 테스트를 Unity 번들 .NET으로 실행

그동안 이 도구는 작업 세션의 임시 폴더에만 있어서 다음 세션에서 사라졌다. 이제 저장소에 남긴다. Unity 에디터가 열려 있어도 동작한다.

## 3. 검증

### 3.1 자동 테스트

- Unity 밖(`verify.sh`): 35개 통과, Unity 전용 1개는 건너뜀
- 에디터 Test Runner: **36/36 통과**

추가한 테스트는 23개다.

**연결 규칙 (15개)**
- 8방향 모두 인접, 같은 칸·2칸 거리·나이트 이동은 불가
- 시작 전 추가 거부
- 대각선 연결
- 인접하지 않은 칸 거부
- 이미 고른 칸 거부
- 되돌리기와 되돌린 뒤 다른 방향으로 연결
- 같은 칸 유지
- 보드 밖 거부
- 서로 다른 종류 연결
- 최대 개수에서 멈춤, 한도에서도 되돌리기 가능
- 1개로는 확정 불가
- 확정 시 순서 유지 후 비움
- 취소
- 새로 시작하면 이전 경로를 버림

**배치·판정 (8개)**
- 6×12 크기 1148×572
- 맨 아래 왼쪽·맨 위 오른쪽 칸 중심 좌표
- 모든 칸 중심 선택
- 판정 원 경계
- 네 칸이 만나는 모서리는 선택 안 됨
- 보드 밖 선택 안 됨
- 빠른 대각선 드래그 시 옆 칸이 끼어들지 않음
- 빠른 가로 드래그 시 중간 칸을 빠뜨리지 않음

### 3.2 조립·실행

- Build All 완료: 선택 외곽선 그래픽 생성, Dev_PuzzleTest 재조립(연결 기록 카드·연결선 층·개수 표시)
- 조립 도구가 이름으로 연결하는 필드 24개가 스크립트의 실제 필드와 모두 일치 (없는 이름은 "누락"으로 나오는 것도 확인)
- **Dev_PuzzleTest Play 진입 확인**: 실행 기록상 Play 시작 → `00_Boot` → `Dev_PuzzleTest` 복귀 순서로 로드됐고 예외가 없었다. **3일차 미확인 항목인 "Dev 씬 Boot 경유 복귀"도 이것으로 해소했다.**

### 3.3 미확인

드래그 조작감(대각선 판정, 선 굵기, 되돌리기 느낌)은 실행 기록에 남지 않아 판단할 수 없다. 사용 중 어색한 점이 있으면 수치를 조정한다.

- 판정 원 크기: `BoardInput`의 `hitRatio`
- 선 굵기·점 크기: `ConnectionView`의 `lineWidth`, `dotSize`

## 4. 참고 사항

- **씬 ID 변경 되돌림**: Build All은 모든 화면을 다시 만들기 때문에 `00_Boot`·`01_Title`에 각각 5,799줄의 diff가 생겼다. 내부 ID를 무시하고 비교해 보니 내용 차이가 0줄이어서 되돌렸다. 이 처리를 `CLAUDE.md` 규칙으로 추가했다.
- **동적 한글 폰트 에셋**: 새 글자가 쓰이면서 파일이 바뀌었지만, 규칙대로 커밋에서 제외했다.
