# 7일차 — 행동력·턴·제거와 낙하

**날짜**: 2026-09-23
**단계**: 2단계 · 퍼즐 프로토타입
**상태**: 완료 · Play 조작감은 기록으로 확인 불가

---

## 1. 목표

- 기본 행동력 6을 두고 보석 1개당 1씩 쓰며, 행동력을 넘는 보석은 고를 수 없게 한다(기획서 5.4).
- 한 턴에는 연결을 한 번만 쓴다.
- **사용자 요청으로 9일차 항목을 앞당겼다**: 사용한 보석이 사라지고, 위의 보석이 내려오고, 빈칸을 새 보석으로 채운다(기획서 5.1).

기획서 계획표의 7일차 항목 중 "서로 다른 보석 섞어 잇기"는 6일차에 이미 끝났다.

---

## 2. 사용자 결정

| 항목 | 결정 |
|---|---|
| 남은 행동력 | **다음 턴으로 이월하지 않는다**. 다음 턴 행동력을 늘리는 것은 균형 보석·스킬의 몫이다 |
| 손을 떼면 | **개수와 관계없이 턴을 쓴다**. 2개 이상이면 보석 사용, **1개면 효과 없이 턴만 소모** |
| 취소 | **보이지 않는 취소 영역**에서 놓으면 턴을 쓰지 않고 취소. 우클릭·ESC 취소도 유지 |
| 취소 표시 | 취소 영역은 그리지 않는다. 드래그 중 들어가면 **화면 가장자리가 옅게 붉어진다** |
| 자동 다음 턴 | 스위치를 두고 **기본은 켬** |
| 행동력 표시 | **보드 상단 중앙** |

취소 표시는 세 번 조정했다.

1. 처음에는 보드 양옆에 "여기에 놓으면 취소" 카드를 두었다.
2. 사용자 요청으로 카드를 없애고, 보이지 않는 영역에 들어가면 화면이 붉어지는 방식으로 바꿨다.
3. 이후 "더 연하게, 범위는 절반 이하로", 다시 "범위 5%까지"로 줄였다.

최종값은 **가장자리 안쪽 5% 구간, 강도 25%**, 화면 전체 채움 없음이다.

## 3. 구현 내용

### 3.1 규칙 (순수 C#)

| 구성 | 역할 |
|---|---|
| `ActionPoints` | 기본 행동력 6, 다음 턴 보너스(한 번만 적용 후 소멸·누적 가능), 기본값 변경은 다음 턴부터, 이월 없음 |
| `PuzzleTurn` | 턴 번호, 한 턴 한 번 행동. 손을 뗄 때 **취소 / 턴만 소모 / 사용** 판정 |
| `BoardGravity` | 사용한 보석 제거 → 같은 열에서 아래로 내림 → 빈 윗칸을 새 보석으로 채움 |

- 행동력은 6일차 `ConnectionPath`에 만들어 둔 최대 개수 자리에 연결했다. 7번째 보석은 `LimitReached`가 된다.
- 보충 순서는 열 0부터, 각 열은 아래 빈칸부터다. 보충용 난수도 보드 시드에서 만든다. **같은 시드와 같은 조작이면 결과도 같다.**
- 피버의 +3(10일차)은 턴 시작 계산에 더할 자리만 두었다.

### 3.2 화면

| 구성 | 역할 |
|---|---|
| `BoardView` | 사용한 보석이 번쩍이며 부풀었다 사라지고, 위 보석이 점점 빨라지며 떨어져 착지 때 살짝 눌린다. 새 보석은 보드 위에서 떨어진다(보드 밖은 마스크로 가림). 턴을 쓴 뒤 대기 중이면 보드를 어둡게 한다 |
| `ActionPointView` | 보드 상단 중앙 탭. 칩 하나가 행동력 1이다. 남은 몫은 금색, 이번 경로 몫은 흐림, 보너스 몫은 청록으로 표시한다. 턴을 쓰면 "사용함", 다음 턴 보너스가 있으면 "다음 턴 +N" |
| `CancelZone` | 보이지 않는 위치 판정 영역. 보드 카드 가장자리 24px 바깥부터 화면 끝까지, 위아래 전체를 덮는다 |
| `CancelOverlay` | 취소 영역에 들어가면 화면 가장자리를 옅게 붉게 물들인다(0.12초 페이드). 입력은 막지 않는다 |
| `PuzzleManager` | 턴 시작, 행동력 한도 적용, 손 뗄 때 판정, 제거·낙하·보충과 연출 연결, 자동 다음 턴 |

### 3.3 Dev_PuzzleTest

- **상단 바**: `턴 N · 연결 가능 / 보석 정리 중 / 다음 턴 대기`, 기본 행동력 −/+, 자동 다음 턴 스위치, 다음 턴 버튼
- **연결 기록**: 사용 시 `턴 3 물물마 3개 사용`, 턴만 소모하면 빨간 글씨로 `턴 4 회 1개 · 턴 소모`
- **하단 안내 문구**: 1개만 놓아도 턴이 소모된다는 점과 취소 방법

### 3.4 공통 부품·그래픽

- `UIFactory`에 체크 스위치(`Toggle`)를 추가했다.
- 화면 가장자리 번짐 그래픽(`ui_vignette`)을 추가했다. 모서리에 대각선 이음매가 생기지 않도록 둥근 사각형(초타원) 기준으로 계산한다.
- 한때 만들었던 취소 X 아이콘은 방식이 바뀌면서 삭제했다.

## 4. 검증

### 4.1 자동 테스트

- Unity 밖(`verify.sh`): 55개 통과, Unity 전용 1개는 건너뜀
- 에디터 Test Runner: **56/56 통과**

추가한 테스트는 20개다.

**행동력 (6개)**
- 기본 6
- 보너스는 한 번만 적용된 뒤 소멸하고, 이번 턴 보너스 몫을 알 수 있음
- 보너스 누적
- 이월 없음
- 기본값 변경은 다음 턴부터
- 잘못된 값 거부

**턴 (6개)**
- 턴 번호 증가
- 한 턴 한 번
- 취소 영역에서 놓으면 개수와 관계없이 취소
- 1개로 놓으면 턴 소모
- 2개 이상이면 사용
- 행동력 6이면 7번째는 이어지지 않음

**제거·낙하·보충 (8개)**
- 아래 칸을 없애면 위가 내려오고 맨 위가 채워짐
- 떨어진 칸 여러 개를 없애도 남은 순서 유지
- 다른 열은 그대로
- 대각선 경로 제거
- 떨어지는 거리와 출발 위치
- 같은 생성 순서면 같은 결과
- 없앤 만큼 채워짐
- 잘못된 입력 거부

### 4.2 미리보기로 디자인 확인

코드로 그린 그래픽을 에디터 밖에서 렌더링해 확인하며 조정했다.

- 연결 중 모습
- 취소 카드 3가지 상태 (최종 방식에서는 사용하지 않음)
- 취소 상태 화면 붉기: 1920×1080 전체 화면 기준으로 여러 번 렌더링하며 강도와 범위를 맞췄다

### 4.3 조립

- Build All 완료. 새 번짐 그래픽이 생성되어 테마에 연결됐다.
- Dev_PuzzleTest에 행동력 탭·취소 영역 2개·붉은 막이 조립됐다.
- 조립 도구가 이름으로 연결하는 필드 44개가 스크립트의 실제 필드와 모두 일치했다.

### 4.4 참고

- 작업 도중 Unity 에디터가 파일을 고치는 중간 상태를 컴파일해 일시적인 컴파일 오류 기록이 남았다. 이후 컴파일은 모두 성공했고, 오류는 최종 코드와 관계없다.
- 실행 기록상 보이는 씬 로드는 Build All이 화면을 조립하며 연 것이다. 실제 드래그·낙하·취소 조작감은 기록으로 확인할 수 없다.

## 5. 참고 사항

- **Build All 뒤 씬 ID만 바뀐 파일**: `00_Boot`·`01_Title`은 내용 차이가 0줄이라 규칙대로 되돌렸다. 동적 한글 폰트 에셋 변경도 제외했다.
- **계획 조정**: 9일차에서 제거·낙하·보충을 뺐다. 9일차에는 동일 종류 연속 +20%, 4연속 강공격, 5연속 특수 보석만 남는다. 특수 보석이 "경로 마지막 칸에 생성"되는 규칙(기획서 5.6)은 9일차에 `BoardGravity`와 함께 조정한다.
- **결정의 결과**: "놓으면 턴 소모" 결정에 따라 보석을 한 번 클릭하고 떼기만 해도 턴이 소모된다.

## 6. 다음 단계

**8일차 — 기본 보석 효과**

연결한 보석이 실제 효과를 낸다. 순서대로 처리한다(기획서 5.5).

전투가 아직 없으므로 효과를 계산해 결과로 돌려주는 규칙과, 이를 확인할 개발용 표시를 먼저 만든다.
