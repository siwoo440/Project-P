# 8일차 — 기본 보석 효과와 공격 대상 선택

**날짜**: 2026-09-23
**단계**: 2단계 · 퍼즐 프로토타입
**상태**: 완료

---

## 1. 목표

- 연결한 보석이 실제 효과를 낸다. **연결 순서대로** 하나씩 처리한다(기획서 5.2·5.5).
  - 물리·마법: 피해 / 회복: 메인 HP / 혼돈: 적 행동 지연 / 균형: 다음 턴 행동력 증가
- 전투(11일차~)가 아직 없으므로, 효과를 계산해 **결과표로 돌려주는 규칙**과 이를 눈으로 확인할 개발용 화면을 만든다.
- **사용자 요청으로 13일차 항목 일부를 앞당겼다**: 공격 대상을 플레이어가 고르고, 대상이 쓰러지면 새 대상을 무작위로 정한다(기획서 6.3).

---

## 2. 사용자 결정

| 항목 | 결정 |
|---|---|
| 효과 수치 | 제안값 그대로 적용 (아래 3.1) |
| 공격 대상 | **플레이어가 클릭해 고른다.** 살아 있는 적만 고를 수 있다 |
| 대상이 쓰러지면 | **살아 있는 적 중 무작위**로 새 대상을 정한다. 남은 적이 없으면 대상 없음 |
| 화면 배치 | 허수아비와 보석 분포의 **자리를 바꿨다**. 허수아비는 상단 가운데, 보석 분포는 보드 오른쪽 |

제가 정한 것(사용자 확인 대상):
- 한 번 연결하는 도중 대상이 쓰러지면 **남은 보석 효과는 새 대상에게** 간다. 쓰러뜨린 공격의 남는 피해는 넘기지 않는다.
- 혼돈 지연도 현재 대상에게 준다.

## 3. 구현 내용

### 3.1 규칙 (순수 C#)

| 구성 | 역할 |
|---|---|
| `CombatStats` | 메인 캐릭터 스탯 묶음(물리 공격·마법 공격·회복력) |
| `GemEffectSettings` | 보석 계수와 혼돈·균형 상한을 한데 묶은 설정 |
| `GemEffectResolver` | 보석 목록을 받아 순서대로 효과를 계산해 결과표(`EffectSummary`)만 돌려준다. 대상에 직접 적용하지 않는다 |
| `GemEffect` | 효과 한 건(`GemEffectEvent`: 종류·양·순번)과 결과표 |
| `TargetSelection` | 공격 대상 선택. 처음엔 순번 0, 클릭으로 변경, 쓰러지면 살아 있는 적 중 무작위 |

효과 수치(임시값, 밸런스 단계에서 재검토):

| 보석 | 효과 |
|---|---|
| 물리 / 마법 / 회복 | 메인 스탯 × 보석 계수(1.0) × 배율. 보석마다 반올림(0.5 올림), 최소 1 |
| 혼돈 | 1개당 대상 행동 +1, **한 번 연결에 최대 +2** |
| 균형 | 1개당 다음 턴 행동력 +1, **다음 턴 보너스 최대 +3** |
| 특수 | 아직 효과 없음(9일차) |

- 배율 자리는 보석 순번별로 받는다. 9일차 동일 종류 연속 +20%, 10일차 피버 +50%가 여기에 들어간다.
- 무작위 대상은 시드를 받는 `System.Random`을 쓴다. 같은 시드면 같은 적을 고른다.

### 3.2 연결

| 구성 | 변경 |
|---|---|
| `GemData` | 보석 계수(`effectCoefficient`, 기본 1) 추가 |
| `PuzzleConfig` | 혼돈 1개당·최대 지연, 균형 1개당·최대 보너스 값 추가 |
| `ActionPoints` | 다음 턴 보너스 상한 추가 |
| `PuzzleManager` | 사용 확정 시 **보석이 사라지기 전에** 종류를 읽어 효과를 계산하고, 균형 보너스를 바로 다음 턴 행동력에 더한 뒤 `EffectsResolved`를 알린다. 턴 시작 알림(`TurnStarted`) 추가 |

### 3.3 Dev_PuzzleTest

```
[현재 시드]   [허수아비 A · B · C]   [연결 기록]
[메인 캐릭터]      [보드 6×12]       [보석 분포]
```

- **메인 캐릭터(왼쪽)**: HP 막대(60/100에서 시작해 회복을 확인), 임시 스탯 물리 10·마법 10·회복력 8을 −/+로 조정, `HP -20` 버튼
- **허수아비 3마리(상단 가운데)**: 왼쪽부터 순번 0·1·2. 칸마다 이름·"행동까지 N턴"·HP(150)를 보여준다
  - 클릭하면 대상. 금색 테두리와 "대상" 표시가 붙는다
  - 쓰러지면 흐려지고 누를 수 없다. `모두 되살리기`로 되살린다
  - 행동 주기 A 2턴 · B 3턴 · C 4턴. 0이 되면 "행동!"만 띄우고 되돌아간다(공격은 11일차 이후)
- **효과 연출**: 0.12초 간격으로 하나씩 적용하고 피해·회복·지연·행동력 숫자가 떠오른다. 처치하면 "처치!"
- **연결 기록**: `물물마 → 피해 30 · 회복 0 · 지연+0 · 행동력+0` 형식, 종류별 색
- **보석 분포(오른쪽)**: 보석 종류별로 한 줄씩 `N개 · N%`

### 3.4 공통 부품

- `UIFactory`에 HP 막대(`Bar`)와 공통 버튼 색 묶음(`StandardColors`)을 추가했다.

## 4. 검증

### 4.1 자동 테스트

- Unity 밖(`verify.sh`): 75개 통과, Unity 전용 1개는 건너뜀. 어셈블리 4종 경고 0
- 에디터 Test Runner: **76/76 통과**

추가한 테스트는 20개다.

**보석 효과 (9개)**
- 보석마다 맞는 스탯 × 계수
- 연결 순서대로 기록
- 섞어 이은 경로의 종류별 합계
- 혼돈 상한 / 균형 상한
- 보석마다 반올림, 최소 1
- 순번별 배율 적용
- 특수 보석은 아직 효과 없음
- 잘못된 입력 거부

**행동력 (1개)**
- 다음 턴 보너스 상한

**공격 대상 (10개)**
- 처음 대상은 맨 왼쪽
- 고르기 / 쓰러진 적·없는 적은 못 고름
- 다른 적이 쓰러지면 대상 유지
- 대상이 쓰러지면 살아 있는 적 중 하나
- 여러 시드에서 남은 적이 골고루 뽑힘
- 같은 시드면 같은 적
- 모두 쓰러지면 대상 없음 / 되살리면 다시 대상
- 잘못된 입력 거부

### 4.2 조립·실행

- Build All 완료(허수아비·보석 분포 자리 바꾼 뒤 다시 조립).
- 조립 도구가 이름으로 연결하는 `EffectTestPanel` 필드 22개가 스크립트와 모두 일치했다.
- Dev_PuzzleTest Play: Boot를 거쳐 퍼즐 화면으로 돌아왔고 실행 중 오류는 없었다.

### 4.3 참고

- 작업 도중 Unity가 고치는 중간 상태를 컴파일해 일시적인 오류 기록(`ApplyEffects` 없음)이 남았다. 이후 컴파일은 모두 성공했다.
- TextMeshPro 내부에서 한 번 난 `IndexOutOfRangeException`은 동적 한글 폰트가 글자를 새로 만들 때 생기는 일시 오류로, 이후 실행에서는 다시 나지 않았다.

## 5. 참고 사항

- **Build All 뒤 씬 ID만 바뀐 파일**: `00_Boot`·`01_Title`은 순서·ID 외 내용 차이가 없어 되돌렸다. 동적 폰트 에셋(한글·LiberationSans fallback) 변경도 제외했다.
- 허수아비의 HP·행동 카운트는 개발용 임시 상태다. 실제 게임에서는 `BattleManager`(11일차~)가 결과표를 적용한다.
- `TargetSelection`은 전투에서도 그대로 쓰도록 `Gameplay/Battle`에 두었다.
